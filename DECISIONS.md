# Decisions

Rulings made while building driftlens, in the program's format:
`Ruling: <what> — <why> — <cost if wrong>`.

- Ruling: compare with structured-merge-diff typed values (client-go's compiled OpenAPI schema) instead of a hand-written JSON diff — it is the library and schema the API server uses for server-side apply, so merge keys, sets and atomic lists behave exactly like `kubectl apply --server-side` — cost if wrong: coupling to SMD v6 and client-go's schema version (1.37); kinds newer than the build fall back to the deduced schema.
- Ruling: CRDs (and objects failing schema validation) use the deduced schema with atomic lists, with a warning — reading CRD OpenAPI from the cluster would need extra RBAC and does not work offline — cost if wrong: coarse list diffs for CRDs (one element change reports the whole list); listed in Limitations and the roadmap.
- Ruling: three-way basis order is last-applied annotation, then managedFields, then none — the annotation stores values, while managedFields only stores ownership — cost if wrong: objects that carry a stale annotation from an old `kubectl apply` but are now managed with SSA get the annotation's verdicts; mitigated because SSA-managed tools strip it.
- Ruling: under SSA, a desired-only field gets origin `unknown`, not a guess — managedFields keeps no record of deletions, so a Git addition and a live deletion are indistinguishable — cost if wrong: more `unknown` (and Drifted status) for pure Git additions under SSA; measured in the mutation eval (SSA origin accuracy 76–80%).
- Ruling: under SSA, a field owned by a non-GitOps manager is `live` even if Git also changed it (no `conflict`) — the applied value is not recorded, so the Git side cannot be proven — cost if wrong: a conflict is under-reported as live drift; documented and measured.
- Ruling: live-only fields owned by no non-GitOps manager are treated as server defaults and hidden (still listed by `--show-ignored`); `reportUnattributed` turns this off — false positives from defaults are the main reason teams stop reading drift reports — cost if wrong: a manual addition made through a GitOps manager name, or present in an offline snapshot without managedFields, is missed by default.
- Ruling: the static defaulter is the default and `--defaults=server` is opt-in — the static table works offline and needs no write RBAC; dry-run create needs `create` permission and runs webhooks — cost if wrong: kinds missing from the static table may show default-only differences; the envtest contract test keeps the table honest for the kinds it covers.
- Ruling: server dry-run defaulting uses a renamed copy (`generateName`) and restores the name — a dry-run create of the real name fails with AlreadyExists for existing objects — cost if wrong: an admission webhook that keys on the object name could default differently.
- Ruling: server-assigned fields (clusterIP, nodePort, PVC volumeName/storageClassName, Job selector labels, Pod nodeName/priority/tolerations, ...) are stripped from live only when Git does not set them, checked per pattern rather than per list element — that keeps pinned values comparable — cost if wrong: if Git pins nodePort on one port, unpinned nodePorts on other ports of the same Service are compared too.
- Ruling: ignore rules prune values from all three sides before typing (Argo CD-style), and hidden differences are recomputed and attributed for `--show-ignored` — pruning first means an ignored field inside an atomic list cannot leak a whole-list difference — cost if wrong: a second comparison per object that has applicable rules (about 2x CPU for those objects).
- Ruling: empty maps or lists present on one side only are never drift — pruning an annotation map's only ignored key would otherwise show a `{}` difference, and the API server drops empty maps anyway — cost if wrong: an intentionally empty struct (`securityContext: {}`) added live by hand is not reported.
- Ruling: added and removed subtrees are reported per list element and per map member — matches how people describe changes ("added env var X", "added label Y") and gives precise owners per key — cost if wrong: a large added struct produces several lines instead of one.
- Ruling: the default GitOps managers are driftlens, argocd-controller, argocd-application-controller, kustomize-controller, helm-controller and kubectl-client-side-apply; the default manual managers are kubectl, kubectl-*, k9s, Mozilla, Lens and kubernetes-dashboard — these are the common names; GitOps wins when both match, so `kubectl-client-side-apply` stays GitOps — cost if wrong: teams that hand-run `kubectl apply` get their manual applies attributed to GitOps; they can override both lists in DriftConfig.
- Ruling: Secret values are always redacted (`<redacted>`) and there is no flag to show them — drift reports end up in CI logs and chat — cost if wrong: you cannot see which way a Secret changed; the change itself and its owner are still reported.
- Ruling: the CLI uses the standard library `flag` package with hand-written subcommands, not cobra — four commands do not justify the dependency — cost if wrong: no shell completion; short and long flag names are registered separately.
- Ruling: live objects are fetched in the desired object's API version, and a version mismatch in a snapshot is an error, not a conversion — conversion needs the API server — cost if wrong: snapshots taken with `kubectl get` in another version cannot be compared; `driftlens snapshot` always writes the right version.
- Ruling: envtest is required by `make check` (`DRIFTLENS_REQUIRE_ENVTEST=1`), and the binaries come from setup-envtest's per-user cache — the program contract forbids Docker or network in `make check`, and envtest needs neither once the cache is filled — cost if wrong: the first `make check` on a new machine needs network to download about 100 MB of binaries.
- Ruling: golden scenario fixtures (`live.yaml`) are captured from envtest by `make fixtures` and committed, with UIDs and timestamps scrubbed — offline replay then uses real managedFields instead of hand-written ones — cost if wrong: regenerating fixtures after a Kubernetes upgrade may change goldens; the live test asserts the same goldens, so any change is caught.
- Ruling: tests simulate kubectl and controllers by sending patches under their field-manager names (kubectl-scale via the scale subresource, kubectl-set, kubectl-edit, kube-controller-manager, ...) instead of running the kubectl binary — keeps tests hermetic and fast — cost if wrong: if a kubectl version uses different manager names, the default `manualManagers` globs (`kubectl`, `kubectl-*`) still match, but the exact actor strings in the docs could differ.
- Ruling: the mutation eval scores against real ground truth and counts documented-limitation misses instead of excluding them; seed 2026 was used during development, seed 7 was run once afterwards — the program requires honest held-out reporting — cost if wrong: none for correctness. The eval only covers edits its author thought of.
- Ruling: one change was made after seeing eval output: added/removed maps are now reported per member (an annotation added to an object that had no annotations used to be reported as the whole map) — it was a real granularity bug found by the eval — cost if wrong: the seed-2026 numbers were computed after this fix, so they are not a pure held-out result; seed 7 is.
